# Возобновляемый плеер Read Aloud

Владелец утвердил в чате: компактный плеер под читаемым сообщением, Play/пауза, ползунок, ±15 секунд, сохранение аудио и позиции после ошибки, продолжение только недостающего фрагмента, подготовка аудио вне долгих UI-запросов. Голос marin, модель gpt-4o-mini-tts и скорость1.2 не меняются.

## Реализация (выбор исполнителя)

- Новые RPC requestChunk/chunkStatus возвращают ID фоновой работы и готовность; HTTP-запросы не ждут TTS. Старые prepare/speakChunk сохраняют совместимость. Новый frontend вызывает prepare без format, чтобы не синтезировать первый фрагмент внутри prepare.
- Фоновые jobs ограничены:2 одновременных синтеза, до128 записей,64MiB аудио,30min idle TTL; одинаковые запросы объединяются. Удаляются сначала завершённые записи; активные работы не вытесняются. Shutdown прерывает работы. Ключ кэша учитывает текст и незасекреченные настройки синтеза, но не содержит API key.
- Фоновый OpenAI запрос получает собственный deadline60s и не более двух попыток20s+35s. Ошибки оплаты/авторизации не повторяются. Job error не уничтожает успешные фрагменты. Нажатие «Продолжить отсюда» повторяет только ошибочный job.
- Frontend хранит оригинальные MP3 каждого полученного фрагмента и его длительность. При повторном проигрывании используются те же bytes, не новый TTS с прежним временным offset. Декодированные AudioBuffer освобождаются вне текущего/соседних фрагментов; bytes сохраняются в пределах сессии страницы.
- Ползунок показывает время по всей записи; длительности ещё не готовых частей оцениваются и помечаются ≈. После декодирования всех частей шкала точная. Выбор неготового места показывает «Подготавливаю аудио». При перемотке во время паузы остаётся пауза; при перемотке во время чтения продолжает чтение с выбранного места.
- Плеер монтируется content script под message action slot, не внутрь absolute toolbar, и не перекрывает composer. Сенсорные кнопки44px+, доступные aria-label и клавиатурный range. Selection reading также получает панель у исходного сообщения.
- Запуск микрофона ставит чтение на паузу с сохранением места. Смена сообщения ставит прежнее на паузу. Ошибка не очищает сессию; кнопка продолжения остаётся в панели.

## Приёмка

Автотесты: background RPC немедленный даже при зависшем синтезе; dedup/cache/error/retry/dispose/bounds; seek назад использует исходное аудио; seek вперёд на pending; pause во время ожидания не запоминает offset предыдущего фрагмента; ошибка позднего фрагмента сохраняет всю предыдущую запись и позицию; ±15 clamp; настоящие DOM-кнопки и range.

Живой smoke: целый длинный ответ ROOT через новые RPC, fault injection только в изолированном тесте, реальные MP3 декодируются; мобильные размеры390/820 и desktop; native plugin/config readback после штатного update. Не заявлять проверку физического iPhone/iPad без неё. Приватные сообщения и аудио не публикуются в GitHub.

Отдельное наблюдение по скриншоту STT: `bb cloud: Not responding` является отказом readiness gate, а не плеера. Проверять отдельно, не выдавать плеер за исправление диктовки и не менять её сервис без причины.
